3D 第三人称 · 用剑者单体战斗系统 · 写实为骨、奇幻为皮
数据源：Data/anatomy.json（人体） · Data/moveset.json（招式）

一、这套系统要解决什么问题

用剑的人的战斗系统，难的不是"能打出几段连招"，而是三件常被跳过的事：

问题常见做法本系统的做法
动作像不像人靠美术手 K，靠人眼审把关节活动度写成数据，逐帧跑断言。"符合人体动作学"是一条能红的命令，不是一个形容词
连招顺不顺每段收招再起手三段走同一条 8 字发力链，第一段的收势就是第二段的起手，中间不做完整收招
技能和华丽的动作怎么接技能是另一套东西第三段上撩的收势本身就是起飞的引信：髋膝踝蹬直把人送离地面 12cm，御剑起飞从这一帧直接开始，中间不需要过渡帧

一句话：机制要长在动作上，而不是贴在动作外面。

剑意（0~100）是唯一的资源轴，而且它只在"打中"的时候长。

  • a1 / a2 / a3 命中各 +25 / +25 / +50 → 一套完整的三连击正好 100
  • 这是刻意的：需求是"连击三次后能御剑起飞"，那么资源曲线就应该让"打完三段"和"攒满"是同一件事
  • 剑意不满时按键 → 要给拒绝反馈（音画提示），不许静默失败。静默失败是"玩家以为游戏坏了"的头号来源

三、地面三连击（写实段）

三段的动作全部来自真实剑术的连续斩逻辑：斜斩 → 反撩 → 上撩，走一条 8 字。

为什么是这条链而不是"砍三下"：

  • 第一段结束后剑停在左下，而这个位置本来就是第二段反手斩的起手。真实剑术的连续斩不需要把剑拉回起点
  • 第二段结束后剑停在右上，而这正是第三段上撩最省力的起点
  • 因此三段的躯干旋转方向和幅度是交替的：右旋 47°（储备）→ 反拧到左旋 28°（释放）→ 再回右旋 → 再反拧。这就是发力链，不是三段孤立动画

帧数据（60fps）

招式总帧起手斩击命中判定收势取消窗口位移
a1 斜斩·右袈裟260–1010–1717–1919–2618–26由躯干反拧带动
a2 反撩·左逆袈裟200–44–99–1111–2012–20重心前后往复
a3 上撩·起势300–77–1313–1616–3018–30蹬直离地 12cm

起手为什么要 10 帧（167ms）：人类视觉反应时间约 200~250ms。第一段是从中立状态发起的，对手必须能读懂；而 a2/a3 是从上一段的收势直接续上，起手可以短。

⚠️ 这条是可读性设计，不是我编的帧数——它来自"攻击需要有可归因的预告窗口，否则玩家会把失败归咎于游戏"这一设计原则。

动作解剖学依据（每段的三处关键）

a1 斜斩

  • 起手把躯干右旋到 47°（骨盆 20 + 腰椎 10 + 下胸 9 + 上胸 8），重心后压到右腿（右膝屈 34°）
  • 斩击由躯干反拧驱动到左旋 28°，躯干前屈 36°，重心压到前腿
  • 手臂只是传导。只动手臂的斩击在画面上就是"挥拍子"，不是挥剑

a2 反撩

  • 起手几乎是 a1 的收势本身（差异只有 4° 级别的躯干角），剑沉到左下外侧
  • 收势躯干重新右旋 37°，身体由前屈转为后仰

a3 上撩

  • 刻意先往下沉（起手剑到右下）——上撩的全部力量来自这一沉
  • 收势是全套里唯一的全身伸展：髋膝踝同时蹬直（踝跖屈 24°）、躯干后仰 22°、肩胛上回旋 24°

四、御剑（形态切换 + 位移 + 穿透）

4.1 起飞 takeoff（72 帧 / 1.2s，不可打断）

四拍：放剑（0–10）→ 剑翻转（10–26）→ 踏上（26–44）→ 拔升（44–72）

  • 剑从手里脱手，在空中翻 90° 落到脚下，人踩上去
  • 这一段切换过程本身也在动：整段位移 +1.4m 高、+0.7m 前。比"原地换形态"好得多，而且翻转本身就是最好的状态切换提示
  • 数据层面这是 pose.sword.detached = true：剑不再是"握在手里的武器"，而是写在根空间里的载具。没有这个开关，御剑根本没法用同一套姿势数据描述

4.2 巡航与悬停

  • 高速巡航用水平踏剑（ride_cruise）：剑身与地面基本平行，冲浪站姿，一手后摆配重
  • 低速悬停用斜插（ride_hover）：剑斜指向下，身体直立
  • 速度感必须五项叠加，缺一项就"飘"：FOV 变化 + 高对比地面纹理流动 + 剑上的留光（拖尾挂在剑上，不是挂在人身上） + 气流 + 相机滞后

4.3 御剑穿身 pierce（21 帧 / 0.35s）

  • 射姿：身体与地面接近水平（根俯仰 78°）、双臂前伸夹紧、双腿后掠。

长距穿刺必须用一条水平的身体表达"我是一条线"——站姿高速冲刺看起来像被拖着走

  • 判定：多段球扫掠 + 按敌人 ID 去重（每个敌人每次冲刺只吃一次）。

绝不用逐帧 capsule 检测 —— 高速下必然穿帧漏判

  • 霸体与无敌分开：前段霸体（0–8 帧）、后段无敌（8–21 帧）。

无敌必须延续到穿出敌人之后 2~3 帧；如果恰好在"离开碰撞体"那一帧结束，就会出现"出敌人的瞬间被打"的经典体感事故

五、剑气凝剑 qi_swords（60 帧）

参数值为什么
剑数63/6/9/12 是可数区间。超过约 20 把，个体就不可读，只能靠整体形状传达信息
第一把提前12 帧用单体预告群体 —— 玩家的视线会跟着第一把剑走。没有这 12 帧，玩家不知道该看哪
发射间隔3 帧（0.05s）依序发射比齐射可读性高一个量级，因为它给了玩家一个节拍器。间隔 <0.03s 会被人耳眼合并成"一下"
排列扇形朝前排列形状本身就是玩法信息：环绕=防御/领域，扇形=有方向，螺旋=包围，纵列=穿刺
伤害形态分段多次命中每次独立命中都能触发顿帧、音效、伤害数字——这些反馈本身就是可读性。DOT 只在领域型剑阵里合适

六、巨剑竖劈 great_cleave（96 帧 / 1.6s）

五拍：指天（0–18）→ 天象（18–48）→ 下落（48–60）→ 命中（60–66）→ 余韵（66–96）

  • 玩家技能用"锁定目标当前位置"，不用区域预警。玩家付出的是 CD 与蓄力时间，不是躲闪技术；打空会带来强烈挫败
  • 但给 telegraphFrames = 36 的落点预警圈（半径 3.2m）—— 玩家能看出"它锁的是我刚才站的地方"，于是学会了"起手就走"。这比纯必中更有趣
  • 下落轨迹本身就是预告：天象拍不是装饰，是本技能最重要的可读性来源
  • 命中必须拉远镜头并留下地裂，否则会失去尺度感（这是巨剑演出最典型的坑：剑变大了，但摄像机和地面参照物没跟着变）

七、斩杀 · 撕裂黑暗 execution（120 帧 / 2s）

需求原话：双手竖握手中剑，画面全黑，由一点变成一竖将黑暗撕开，角色穿到以敌人为圆心的直径对面。

四个决定成败的细节

① 第 3 拍：为什么是"由一点变成一竖"

一个"点"先于人眼识别出一个"形状"之前就出现，所以观众的第一反应是"有光"；光长成线，第二反应才是"被切开了"。由点到线是让观众参与生成那条切割线——比自己直接看到一条线更有力。

技术要点（三件缺一不可）：

  • 光缝必须边缘锐利、中心过曝。锐利边缘读作"切口"，柔和辉光读作"光柱"，语义完全不同
  • 在 bloom 之上叠各向异性竖直拉伸（横向 sigma ≪ 纵向）。只用圆形 bloom 会变成光球，语义是"发光"而不是"切开"
  • 扩张必须加速：1~2px 停留 2~3 帧 → 猛地展开。线性扩张读起来像"光在变粗"，加速的扩张读起来像"裂开了"

② 第 4 拍：为什么用反色而不是纯白

白闪适合"物理冲击"；负片（反色）适合"空间被切开"——因为反色是"世界的颜色规则被违反了"，语义上比过曝更"非人"。

③ 第 5 拍：换位用瞬移，不用残影

残影读作"跑过去"，会破坏"穿过去"的语义。位移距离 = 2×敌人半径 + 2×自身半径 + 0.2m 余量，保证换位后碰撞体不重叠——否则物理系统会立刻把两人推开，那一推会毁掉整段演出。

相机不该瞬移：以 0.3s 插值到新的身后位。相机比角色慢，是这段演出有没有电影感的分水岭。

④ 第 6 拍：敌人反应延迟（最重要的一拍）

换位演出的心理机制是先给结果，再让观众自己补原因。玩家看到的是"我已经在敌人背后了"，然后敌人过了几帧才倒下——这几帧就是玩家的脑子在跑回放的时间。

如果敌人和角色同时到位、同时倒下，整段演出会变成打了个响指，冲击力全部消失。

音效

静音（留 20~60Hz rumble，并把混响尾巴一起切掉）→ 撕裂 → 低频 boom → 金属尾音

  • 静音不等于无声：留极低频让"空间本身"消失，这才是"全黑"的听觉对应物
  • 静音段要比体感舒适值再长 1~2 帧，但不超过 0.5s（超过会被判定为卡顿）
  • 顿帧与音效起音必须锁相

八、人体动作学保障体系

这是本系统与"看起来差不多"的做法真正的分界。"符合人体动作学"被拆成了四层可执行断言。

第 0 层：骨架自证（audit.mjs --axes）

在写任何一个姿势之前，先证明骨架本身的定义是对的：

  • 轴向自证：给每个 dof 一个正值，打印它让末端（以及一个离轴标记点）往哪个世界方向动，再和它自称的解剖学含义比对。

为什么需要离轴探针：轴向自转不会移动骨骼末端，光看末端那几行（骨盆旋转、髋内外旋、前臂旋前）其实什么都没验证——而躯干旋转恰恰是挥砍发力的核心。

实测结果：全部 45 条轴向语义与声明一致。

  • 镜像自证：给 .L 与 .R 同一组语义角度，检查 .R 是否是 .L 的几何镜像。实测 8 对骨骼误差 0.000e+0，规则 (x, -y, -z) 成立。

这条规则让左右两侧共享同一套 dof 名与同一套 ROM，姿势数据可以对称书写。

第 1 层：关节活动度（ROM）

22 根骨骼、45 个 dof，每个都有 [min, max]。逐帧比对实际施加的关节角（包括 IK 反解出来的手臂角）。

第 2 层：几何与耦合约束

单根骨骼合法不等于整个姿势成立。9 条耦合断言，每条都对应一个真实的解剖事实：

约束内容为什么
two_hand_grip_reach两腕距离 ∈ [3cm, 40cm]双手握剑是一个纯几何可达性问题。用关节角硬凑两只手碰不到同一根剑柄
trunk_rotation_budget骨盆+腰椎+下胸+上胸旋转合计 ≤ ±75°分段各转一点，单看每根都合法，加起来就是"上身拧断"
trunk_side_budget躯干侧屈合计 ≤ ±45°同上
shoulder_impingement肩外展 >90° 时必须有外旋 ≥0大结节会撞肩峰，真实人体靠外旋绕开骨性结构
scapular_rhythm肩外展 >90° 时肩胛上提 ≥8°锁骨纹丝不动而上臂硬抬，是最容易被一眼看出的假动作
knee_tibial_rotation_gate膝屈 <20° 时胫骨自转 ≤6°伸直 + 大自转＝十字韧带损伤的姿势

第 3 层：动力学（流畅性）

单帧合法抓不到卡顿与抽搐，所以还有：

  • 角速度 / 角加速度
  • 剑尖速度与轨迹总长（剑尖峰值速度上限 45 m/s；实测研究里优秀剑手的剑尖在 20~30 m/s 量级）
  • 支撑相足部滑步
  • IK 可达性（手伸到身体够不着的地方要报出来）
角速度必须用四元数真实夹角算，不能用欧拉分量之差。欧拉分解在 ±90° 奇异点会翻分支（+90 跳到 −90），差值 180° 会被误读成 10800°/s 的假速度尖峰。这一条踩过。

第 3.5 层：手臂为什么不用欧拉判

肩关节真正外展超过 90°（手臂举过头）时，Rz·Rx·Ry 的欧拉分解会在 x/y/z 之间翻分支，报出 horizFlexion = ±170 这种数值——那是分解的假象，不是人真的把肩膀拧了 170°。

所以手臂改判三个不受参数化影响的物理量：

1. 可达性：目标点有没有超出臂长

2. 肘屈曲 ∈ [−3°, 150°]（负值就是反关节）

3. 肩摆幅 ≤ 175°

手腕用 swing-twist（摆幅 ≤85°、扭转 ±25°）。

九、姿态系统为什么用 IK

「双手握剑」是核心约束，但两只手必须能同时够到同一根剑柄，这是一个几何可达性问题。如果姿态只用关节角来写，要让左右手在空间里正好碰到一起，是纯碰运气。

所以本系统的分工是：

部位表达方式理由
躯干 / 腿 / 头 / 肩带关节角（解剖学 dof 名）作者想得清楚，且这些关节的活动范围本来就该硬约束
手臂手在世界的位置（根空间）+ IK 反解剑在哪比肩角多少度重要得多
刀锋方向（可选）给了它，手的朝向由刀锋反推，腕角再交给 ROM 审计。想让刀锋指向手腕到不了的方向？审计会红——这是设计意图

姿态数据支持 extends 继承：多数字势只改几个关节，不该整段重抄。

解算器里三个必须做对的地方

1. 上臂的世界旋转必须同时满足两条约束：骨长方向 → upperDir，且「前臂铰链轴」→ 弯折平面法线。

只做第一条而放任自转，肘关节会变成万向节（实测 carryAngle = −115°，而肘的解剖极限是 ±6°）。

2. 肘位要在"肩—腕轴"的整圈上搜索，代价函数同时惩罚：反关节（硬约束）、手腕过弯、偏离极向量、肘几乎伸直、以及与上一帧不连续。

搜索范围限制在极向量一侧的 ±90°——放开整圈会让相邻两帧分别选中"对面的那个极小值"，手骨帧间整转 180°。

3. 极向量必须先投影到垂直于肩腕轴的平面再用于比较。接近平行时投影退化成噪声，代价函数随之变成随机数，搜索逐帧乱跳分支（报表上就是 172°/帧 的整数字尖峰）。

十、"流畅"是怎么实现的

不是靠调缓动曲线，而是四件事：

1. 单调三次 Hermite 插值（Fritsch–Carlson），不是 Catmull-Rom。

Catmull-Rom 会过冲，过冲会把手脚推出 ROM 之外——而"姿势合法"是这个项目的地基，不能为了手感把它抵押掉。

也不是平滑步：平滑步在每个关键帧处速度为 0，连招会一跳一停。单调三次是 C1 连续且不过冲。

2. 加速斩的"快"来自关键帧的疏密，不是再叠一层时间弯曲。叠上去会双重压缩，把 5 帧的动作压进 1 帧（实测剑尖瞬间到 122 m/s＝每帧 2 米，画面上是瞬移）。

3. 离散状态整段切换：剑是否脱手、是否双手握，这类状态不参与插值，按"最近的关键帧"整段切换。剑从手里到脚下的过程本身就是一个事件，不是渐变。

4. 时间连续性：IK 逐帧求解会把上一帧的解作为 hint 传进去并施加惩罚。这不是审计器的补丁，而是解算器应有的接口——运行时同样需要。

⚠️ 已知未收口（16 条，且每一条都有明确根因与修法）

招式剩余问题根因修法
a13 条（腕摆幅/扭转、可达 0.9cm、角速度 4068°/s）中间帧已在弧上补了一个，但弧还不够密再补 1~2 个中间帧
a2 a3各 2 条（角加速 ~1.27e5、剑尖 ~53 m/s）斩击相只有 5~7 帧，扫过 140°+ 的刀锋弧把斩击相延长 1~2 帧，或把起止姿态的刀锋夹角收小
takeoff1 条（剑尖 161 m/s @f10）是"剑脱手"那一帧的状态切换：附着态与脱手态的目标点没有对齐到同一位置让 t_release 的 sword.pos 与该帧的手骨位置严格对齐（已改过一次，仍需再对齐一次）
pierce2 条（角速度 6390°/s、角加速 3.8e5）射姿转换时手的目标点跨度大在 pierce_wind → pierce 之间补中间帧
great_cleave2 条（角速度 4471°/s @f76）收招相从"落"回到"悬停"跨度过大收招相延长或补帧

共性：剩下的全部是同一个根因——手部目标点在通道空间里按直线插值，而真实的挥砍手走的是弧线；当两点跨度大时，那条弦会从肩膀里穿过去（实测第 13 帧手距肩只剩 3cm，整条手臂塌成一团）。

统一的解法是在弧上补中间帧，而不是放宽阈值。工具已经把"哪一招哪一帧"指出来了。
